# COOKX 菜谱数据模型 v3

本文件描述当前实现的存储契约。旧数据按用户要求清空，不提供字符串列表到 v3 的迁移。

## 主结构

```text
KitchenState（schemaVersion = 3）
├── family
├── recipes[]
│   ├── id / familyId / name / servings / tags / coverUri
│   ├── ingredients[]：RecipeIngredient
│   ├── phases[]
│   │   ├── prep：有序 RecipeStep[]
│   │   └── cook：有序 RecipeStep[]
│   ├── source：RecipeSource?
│   └── reviewItems[]
├── records[]：独立的日期、餐次与制作心得
├── customTags / favoriteTags
├── pantryItems[]
└── shoppingMemos[]
```

两个阶段都保留，可以有一个阶段为空；至少需要一个实际步骤。步骤顺序由各阶段内列表表达，播放时临时展开，不重复存储一份总步骤文本。

## 食材与关联

`RecipeIngredient` 包含稳定 `id`、`name`、可空的 `quantityText`、可空数值 `quantity` / `unit`、来源证据 `evidence`。

- 手动录入使用名称与用量原文；空用量仍为空，不自动补成“适量”。
- 数值与原文可同时保留，显示时优先保留原文，不自动换算“勺”为毫升。
- 采购便签直接使用食材 ID，更新顺序或用量不会使勾选关联到别的食材；与家中已有食材按名称确定匹配，不再解析“名称＋数量”字符串。
- 同一食材可被不同步骤引用，各步骤可有不同的本步用量；未填写本步用量时只显示名称，不擅自使用全菜总量。

`StepIngredientUse` 通过 `ingredientId` 引用本菜食材，并可记录本步 `quantityText` 或 `quantity` / `unit`。保存时拒绝悬空引用和同一步的重复引用。

## 步骤与模板

`RecipeStep` 字段：

| 字段 | 含义 |
| --- | --- |
| id | 阶段内排序、跨阶段移动时保留的稳定标识 |
| kind | `custom` 或 `template` |
| operationType | 清洗、去皮、切块、切片、切丝、切丁、焯水、腌制、搅拌、翻炒、炒香、炖煮、调味、装盘、其他 |
| title / description | 保存后可独立展示的具体做法 |
| ingredients | 本步食材引用与用量 |
| parameters | 可选火候、温度、尺寸、完成标准 |
| timer | 可选时长（秒）与启动条件 |
| imageUri | 可选步骤图片位置；当前录入页面尚不上传图片 |
| templateRef | 标准模板 ID、版本、模板用料槽位到菜谱食材 ID 的绑定 |
| evidence | 原文或图片证据引用 |

操作类型决定图标，不决定是不是模板步骤。自定义步骤可以使用任何操作图标；无法识别时使用 `other`。

模板清单仅保存在 `app/src/main/assets/presets/step-templates.json`。`OperationTemplate` 读取 ID、版本、操作类型、建议阶段、参数、条件动作和手动计时配置。当前支持食材／食材列表、原文用量、文字、分钟数、开关和食材下料顺序。必选食材及必填用量必须填写；启用可选动作后才要求其食材，未启用动作及其用料不写入播放副本。

套用后，将按条件筛选的动作与具体用料分行生成做法，和参数、计时、绑定结果一起复制为 `RecipeStep`，保留 `templateRef`。模板参数保存在 `templateRef.values`，用于恢复编辑；食材列表绑定键为 `参数ID:索引`。播放只读步骤内容，不根据模板 ID 实时重建；以后模板改变不会自动改写旧菜谱。

当前模板目录只读，读取六个已确认模板：肉丝腌制、切滚刀块、切均匀块、肉类焯水、西兰花焯水、葱姜蒜爆香。肉类焯水只采用冷水下锅；西兰花过凉可选；香料可一起下或排序。未填写时长不生成计时器；填写焯水时长时必须提供起点。模板中的多个动作仍为同一制作页。模板维护权限、家庭模板及升级策略仍留待产品讨论。

修改标准步骤的核心做法时，可转为自定义步骤；不继续声称是未经修改的标准模板。阶段、排序、删除和食材关联在编辑器中显式维护。

## 来源与待确认项

- `RecipeSource` 保留平台、原帖 URL、标题、作者与帖子 ID，不保存小红书登录 Cookie 或临时访问凭据。
- `EvidenceRef` 区分正文与图片，索引从 1 开始，允许保留原文片段。
- `ReviewItem` 保存代码、说明以及食材／步骤 ID 引用；可记录缺失用量、描述冲突、未知尺寸等。
- 当前模型为后续导入提供承载能力，不表示 App 已能调用小红书 MCP、理解图片或自动导入调研 JSON。
- 调研草稿 `cookx.recipe-import-experiment.v0.1` 与正式 schema 3 不直接兼容。后续需要明确的转换、引用校验与确认流程，再填写家庭和稳定 ID；禁止把未确认的来源缺失内容补成事实。

## 保存与会话边界

保存前校验阶段顺序、唯一 ID、食材引用、模板绑定、正数数量、有效计时、家庭归属和记录归属。校验失败不会替换上一份有效数据。

日期与餐次属于 `CookingRecord`；计时截止时间、当前步骤与完成页输入属于当次制作会话，不写回菜谱或模板。日期餐次仍在开始时预选、只在完成页显示设置。

仓储使用 `cookx_kitchen_v3`，固定 `schemaVersion = 3`，不读取旧 v1/v2 存储。默认状态无家庭、菜谱、库存或制作记录，示例需要用户主动添加。

## 预设标签与首页分类

标签唯一正式清单为 `app/src/main/assets/presets/tags.json`，包含版本及 33 个稳定 ID／名称。仓储加载时注入只读预设名称，不将预设清单复制到用户 JSON；当前菜谱标签、自定义标签及常用标签顺序继续按名称保存。没有第二份 Kotlin 预设标签清单。

首页沿用家庭常用标签顺序，仅展示至少匹配一道当前家庭菜谱的标签。“未打标签”也仅在存在无标签菜谱时出现；“全部”始终保留。标签变空或移出常用列表后，选中项回到“全部”。隐藏只影响首页，录入、标签管理中的全部预设与自定义标签仍可用。

# COOKX 产品想法与讨论记录

更新日期：2026-11-17

本文持续记录产品讨论。明确区分用户已提出的需求与讨论中的建议；建议不代表已经确定的开发范围。当前仍处于产品构思阶段。

## 一、已提出的产品方向

COOKX 是一个从记录菜谱出发的 Android App。记录菜谱是核心功能，家庭点菜、食材管理和 Agent 等功能围绕菜谱展开。

### 1. 菜谱与做菜辅助

- 通过一道菜的图片进入详情，查看所需食材、上次制作时间。
- 点击“开始制作”进入做菜辅助模式。
- 辅助模式类似 PPT，每一页展示一个步骤及说明。
- 模式内提供做菜时常用的工具，例如计时器。
- 完成后支持拍照上传菜品照片。
- 记录本次制作的评价，例如难易程度、口味等；具体评分项目和尺度待讨论。

### 2. 家庭与点菜

- 从产品最初版本就引入家庭概念，家庭是基础产品概念。
- 一个人也可以组成家庭，单人使用和多人家庭使用都在这套概念下成立。
- 每个用户可以创建家庭。
- 其他用户通过家庭邀请码加入家庭。
- 家庭共用一本菜谱，菜谱以家庭为归属。
- 家庭成员可以对菜谱进行点菜和打分。
- 成员退出家庭及退出时复制菜谱的功能初期不考虑。后续方向为成员退出时可选择复制菜谱，具体范围和规则届时讨论。
- 家庭数量、角色、菜谱编辑权限、点菜处理方式及评分归属待讨论。

### 3. “囤囤鼠”食材管理

- 记录每次购买食材的花费。
- 记录冰箱剩余食材量。
- 记录调料台的情况。
- 库存如何录入和更新、采用何种计量方式、是否与做菜自动联动待讨论。

### 4. 小红书内容导入

- 希望接入读取小红书帖子。
- 希望将小红书经验帖子转换为可以使用的菜谱。
- 内容获取方式、支持的帖子类型和实际接入能力尚未验证，当前不承诺任意链接均可读取。

### 5. Agent

- 根据用户一天做的菜，提供健康相关的建议。
- 协助处理食材与调料的替换。
- 协助将小红书经验帖子转换成菜谱。
- 建议如何确认和保存、Agent 是否可以直接修改记录、使用哪些用户数据待讨论。

## 二、建议的产品组织方式（待确认）

### 1. 以一次做菜形成核心闭环

记录或导入菜谱 → 查看食材 → 开始制作 → 分步辅助与计时 → 完成拍照、评价 → 下次参考历史。

建议首个可用版本在家庭概念下优先完整走通这条流程。库存和 Agent 的具体能力可后续分阶段接入；家庭从最初版本就存在，具体协作功能的交付范围待讨论。

建议首次使用时提供“创建家庭”和“加入家庭”入口，独自使用的用户也可以创建只有自己的家庭。是否自动创建默认家庭、是否要求立即命名，以及具体引导方式尚未确定。

### 2. 将菜谱与每次制作记录分开

- **菜谱**：菜名、封面、食材、用量、步骤、来源等可复用内容。
- **制作记录**：某一次制作的时间、照片、实际替换、评价和备注。
- “上次制作时间”由制作记录产生，历史照片和评价也能按次回看。
- 做完后可以选择把经验修改到菜谱，避免一次临时替换直接覆盖原配方。

### 3. 将做菜者评价与家庭成员评价分开

- 做菜者记录制作体验，例如难易程度、是否成功和下次改进点。
- 家庭成员记录用餐反馈，例如口味与想不想再吃。
- 家庭成员可对菜谱表达点菜意愿；是否同时支持对某一次成品评价，待讨论。

### 4. 做菜辅助围绕厨房实际操作设计

- 大字、清楚的步骤编号、容易触达的上一步和下一步。
- 当前步骤直接展示本步所需食材与用量，减少返回详情查找。
- 计时器与步骤关联，切换步骤后仍能继续计时；多计时器需求待讨论。
- 支持中途退出后继续；进入辅助模式时是否保持屏幕常亮，待设计。

### 5. 库存维护从低负担开始

- 可先讨论“充足／不多了／用完了”等粗略状态，减少每次称重录入的负担。
- 购买记录、库存状态和调料余量可以独立维护，再讨论自动扣减与补货提醒。
- 若支持做菜后扣减，需允许用户确认实际消耗及替换，避免库存误差不断累积。

### 6. Agent 的输出可核对、可修正

- 导入菜谱时保留原帖来源；缺失或推测的用量、时间等信息明确标记，并由用户确认后保存。
- 替换建议说明适用条件，以及可能需要调整的用量或做法。
- “做过的菜”与“实际吃了什么”分开记录：家庭共享、人数和食用份量会影响饮食分析；信息不足时不输出精确的个人营养结论。
- 用户确认后再将建议应用到菜谱或库存，具体自动化范围待讨论。

## 三、优先讨论的问题

1. **主要录入方式**：手动整理自己的菜谱，还是以小红书等外部内容导入为主？
2. **点菜含义**：表达“想吃”，还是提交某天、某顿的用餐请求？
3. **库存精度**：精确数量，还是容易维护的余量状态？

## 四、讨论与决策记录

### 2026-11-17：初始想法

- 用户提出菜谱记录、分步做菜辅助、制作后照片与评分、家庭邀请码与点菜评分、“囤囤鼠”、小红书导入和 Agent 八项方向。
- 本文第二部分为基于这些方向的完善建议，尚未确认为最终需求。
- 尚未确定首版范围、界面结构、技术实现或开发排期。

### 2026-11-17：家庭从最初版本引入

- 用户确定：从最开始就引入家庭概念，一个人也可以作为家庭存在。
- 已据此调整首版建议，移除“个人优先还是家庭优先”的待决问题。
- 该决定尚未确定菜谱与库存的归属、默认家庭创建方式或多家庭支持规则。

### 2026-11-17：家庭共用菜谱

- 用户确定：家庭共用一本菜谱。
- 用户提出后续成员退出时可选择复制菜谱；成员退出相关问题初期暂不考虑。
- 已移除菜谱归属的待决问题。菜谱编辑权限和库存归属仍待讨论。

### 2026-11-17：初始化基础工程

- 用户要求：使用官方 Android skills 初始化 Kotlin + Jetpack Compose 工程，结合现有产品构想搭建基础工程并在模拟器验证。
- 本次实现选择：单模块、Material 3、Navigation 3、ViewModel、本地存储；家庭由用户主动创建，菜谱与每次制作记录分别保存，支持分步制作与页面内计时。
- 示例菜谱需用户主动添加，并明确标注。基础版包含手动录入和制作心得，尚无真实照片上传与独立评分项。
- 邀请码联网协作、点菜、库存、小红书与 Agent 尚未接入；本次原型不将这些能力及原有待讨论建议自动确认为首版承诺。
